# Miamibloco Fundraiser Finder

A no-build, single-page dashboard for Miamibloco's Give Miami Day fundraisers.
The page is static; `data.js` is generated by a scraper and refreshed on a
schedule.

## Run it

```sh
open index.html
```

Or serve it locally:

```sh
python3 -m http.server 8000
# then visit http://localhost:8000
```

No install or build step required. `index.html` loads `data.js` with a normal
script tag, so it also works when opened directly from disk.

## What it does

- Searches all fundraisers by name, instrument, or role.
- Links each result to its Give Miami Day page
  (`https://www.givemiamiday.org/story/<urn>`).
- Shows campaign progress, how many people are participating, and a single
  **By Section** participation leaderboard.
- The leaderboard combines the instrument sections (Caixa, Repique, Surdo,
  Tamborim, Ganzá, Timbau) with Teaching Artist and Passista.
- Supports keyboard search (`/` to focus, `↓` to enter results, `Enter` to open
  a single match, `Esc` to clear).

## Update the data

```sh
python3 scripts/scrape.py
```

This fetches the live Give Miami Day data and rewrites `data.js` atomically.
Use `--dry-run` to print a summary without writing:

```sh
python3 scripts/scrape.py --dry-run
```

Use `--output` to write somewhere else:

```sh
python3 scripts/scrape.py --output /tmp/data.js
```

The scraper:

1. Reads campaign totals from
   `/api/v4/story/Miamibloco.json?include_all_details=true&requested_type=organization`.
2. Paginates
   `/api/v4/story/Miamibloco/supporting_fundraisers.json?page=N&limit=6`
   until the list is exhausted. The API caps each page at 6, so it takes
   about 13 requests.
3. Parses each fundraiser title into a name, instruments, and role.
4. Writes `data.js` in the shape:

```js
window.DASHBOARD_DATA = {
  campaign: {
    goalCents: 2500000,
    raisedCents: 0,
    snapshot: "2026-11-06",
    sourceUrl: "https://www.givemiamiday.org/organization/Miamibloco"
  },
  fundraisers: [
    {
      name: "Guillermo",
      instruments: ["Repique"],
      role: "Student Member",
      raisedCents: 0,
      goalCents: 30500,
      urn: "4mj02f",
      photo: "https://..."
    }
  ]
};
```

The script exits non-zero and leaves the old `data.js` untouched if a request
fails, no fundraisers are returned, a title cannot be parsed, or duplicate URNs
appear. If only the date changed and the numbers did not, it preserves the
previous snapshot date so no empty commit is created.

### Parsing notes

- Amounts are in cents.
- `urn` is the last part of the person's story URL.
- `instruments` is an array so joint pages (for example, Geisy & JJ) can appear
  in more than one instrument section.
- Roles in the source data are `Student Member`, `Teaching Artist`, `Passista`,
  and `Hype Squad`. Only `Teaching Artist` and `Passista` are shown as sections
  and role tags; student and hype squad roles are intentionally left out of the
  UI.
- A few pages do not follow the usual `Name - Instrument (Role)` pattern.
  These are handled explicitly in `parse_fundraiser()`:
  Geisy & JJ, Michelle (Passista), and VP KeKe.

## Participation formula

Section participation is calculated per section as:

```
people in the section with more than $0 raised ÷ people in the section
```

A $0 page has not participated yet; any amount above $0 counts as participating.

Overall progress uses the campaign's raised amount and $25,000 goal from the
campaign API. "Raised so far" is the sum of the personal fundraiser pages.

## Scheduled updates with GitHub Actions

The workflow at `.github/workflows/update-data.yml`:

1. Runs every 15 minutes and can also be started manually.
2. Runs `python3 scripts/scrape.py`.
3. Commits `data.js` only when the data changed.
4. Deploys `index.html` and `data.js` to GitHub Pages when there is a change.

### One-time setup

1. Create a GitHub repository and push this folder to the default branch
   (`main`).
2. In the repository, open **Settings → Pages**.
3. Set **Source** to **GitHub Actions**.
4. Run the workflow once from the **Actions** tab (`Update fundraiser data` →
   **Run workflow**).

After that, updates run automatically. If a scheduled run fails, GitHub sends
the usual workflow failure notification.

After Give Miami Day, change the cron in
`.github/workflows/update-data.yml` from `*/15 * * * *` to `0 * * * *` to run
hourly. The workflow only commits when the numbers change.
